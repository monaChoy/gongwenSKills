# 文种骨架（国企/央企）

供起草选结构。按「读者需要知道什么、决定什么」增删。**用户提供的格式模板优先于本章。** 文中条数、页数为参考，非硬性通过条件。

## 请示

结构：拟请示事项 → 理由与依据 → 方案、资源及影响 → 拟提请决定的内容。

要点：一文一事；金额、数量、时限给依据（估算口径注明）；拟决定事项写成可批复表述。

## 报告

结构：报告事项与核心情况 → 事实与工作情况 → 问题及影响 → 已采取措施与下一步。

要点：区分已做、成效与拟安排；重要评价附依据。正式行文按已明确制度确认文种与结尾；出现求批经费/方案时，判断是否应改请示或另文。制度不明标【待确认】。内部会议汇报按会议目的组织，不因名称含「报告」套正式行文全部要求。

## 进展/专项汇报

进展默认：核心结论 → 概况与当前状态 → 计划与实际（偏差及原因）→ 问题风险及措施 → 下一步 → 需协调/决策事项。

专项默认：总体情况 → 重点工作与成效 → 存在问题 → 后续安排；需快判时可先概述结论。

要点：进展用实际口径；延期写原因、影响与补救；依赖写清我方已做与对方待办（事项、时限）。成效须可核实；问题与整改对应。无政策、无案例也可成文。

## 通知

结构：事项与对象 → 具体要求 → 责任、时限及办理方式。

要点：每条可执行、可检查——谁、何时前、做什么、如何反馈。

## 工作方案

结构：背景与目标 → 总体思路/原则 → 任务分工与清单 → 进度安排 → 保障与风险 → 有关要求。

要点：目标可检查；任务落到责任单位；节点与资源匹配；风险写预案，不空喊「加强」。

## 会议纪要

结构：会议基本信息 → 议定事项（分条）→ 分工与时限 → 其他说明。

要点：只写议定与可核对安排；发言摘要从简；责任、节点未定时标【待确认】或写拟定。

## 党建短材料

结构：依据或要求 → 具体动作 → 可核成效或阶段性结果 → 不足与下一步（按需）。

要点：动作具体到单位/岗位/事项；成效不超证据；避免空泛「提高认识」堆砌。

## 经验材料

结构：背景与问题 → 主要做法（分条）→ 成效与启示 → 适用边界。

要点：做法可复用；成效有数字或事实；写清前提，避免写成万能经验。

## 情况说明

结构：事项背景 → 已核实事实与时间过程 → 原因及影响 → 已采取措施与后续安排。

要点：事实依已核验资料；原因区分已核实与待查证。责任与时限未明确时标【待确认】。

## 信息化/项目前期建设思路汇报

结构：必要性依据 → 目标体系 → 总体架构 → 清单对应 → 实施与调研需求。

要点：

- 有直接相关上级文件时：全名 + 文号 + 印发时间，拆成可呼应的发力点；否则从业务需求立论，不硬挂政策。
- 目标覆盖关键维度即可。有依据可用「旧方式 → 新方式」；现状未核实则直接写拟建机制，不贬低现状。新方式标明拟建/计划/目标。
- 对标：项目名 + 有据数据 + 成效，并标注为对标、与本项目区分。
- 架构讲清分层与模块，清单对应层级（系统/设备/服务），保留名称、单位、数量及清单状态（方案/采购等）。
- 调研问设计能回答的问题（利旧、范围精度、建模对象、用户权限、工期、预算口径）。预算区分估算/概算/报价/批复。需对方行动时写入协调事项。

## 配套载体转换

- 一页简报：注明时间范围；优先关键变化、风险与所需行动。
- PPT 提纲：按页主题与必要结论；数字保留单位、统计期、限定词。
- 发言稿：按指定时长取舍；保留事实依据与行动诉求。

内容提纲与实际文件制作分开交付；未检查实际文件前，不对版式与页面完整性下结论。
