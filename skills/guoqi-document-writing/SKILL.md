# 国企材料成稿

为中国国企/央企场景写可用成稿：呈批、部署落实、经营与党建并重。默认语气是企业材料，不是政府公文。完整起草在本技能；挑刺式「对不对」用 `leader-review`。

## 输出契约

默认交付**完整成稿**（标题齐全、可直接使用的正文），并列出影响使用的信息缺口。用户给出或粘贴了模板时，**严格按该模板**的结构、栏目与顺序生成，覆盖内置文种骨架；不另开「有无模板」问答流程。

## 工作流程

| 步 | 动作 |
| --- | --- |
| 1 路由 | 识别文种、读者、目的、载体与篇幅；涉及项目时确认阶段 |
| 2 骨架 | 先出标题层级与段意（或按用户模板列栏目），不急于长文 |
| 3 展开 | 按骨架写成完整正文；缺口标【待确认】 |
| 4 自查 | 对照 [像不像核对表](references/likeness-checklist.md) 与下方原则 |
| 5 交付 | 成稿 + 必要缺口说明；改稿另附关键改动 |

用户只要骨架时停在第 2 步。改稿：先明确修改范围与须保留的事实、限定、立场，再改；冲突说明依据，无法判定则保留分歧。

## 文种路由（按需读模板）

读取 [文种骨架](references/templates.md) 对应章节。常见映射：

| 意图 | 文种 |
| --- | --- |
| 求批一件事 | 请示 |
| 陈述情况/工作 | 报告 |
| 同步进度、风险、协调 | 进展/专项汇报 |
| 部署要求、可检查 | 通知 |
| 怎么干、清单与节奏 | 工作方案 |
| 议定事项留痕 | 会议纪要 |
| 党建短经验/做法 | 党建短材料 |
| 做法可推广 | 经验材料 |

建设思路、情况说明等见模板专节。不为凑结构硬加政策、案例。

## 共用原则

1. **来源与状态分开。** 区分已核实事实、计划/目标、建议/诉求、待核实。用户陈述或旧稿≠已核验；关键结论能回溯到材料及适用时间。
2. **把住事实口径。** 规划/采购/实施/验收/运行分开写；估算/概算/报价/批复预算分开写。数字带单位、分母、统计期、范围及「约、拟、不超过」等限定；润色不扩大成果、不新增承诺。
3. **结构服务读者。** 按读者要知道什么、决定什么取舍。风险、经费依据、验收状态、诉求即使暂缺也要标缺口。
4. **问题与行动匹配。** 写清问题、影响、依赖与已采取措施；需他方行动时写事项、责任、时限。不作无依据指责。
5. **评价有证据。** 不编造数字、文号、案例、沟通史。成效与现状不超出证据；「旧→新」对比须有现状依据。
6. **旧材料须清理。** 防旧模板项目名、单位、地名、规模混入；对标须标注来源与边界。跨载体转换时结论、状态、数字、诉求一致。

## 表达要点（国企）

- 正式、准确、克制；多用可核对的状态与动作，少用空泛动员套话。
- 对上讲清拟决定事项与依据；对下讲清谁、何时、做什么、如何反馈。
- 标题宜实：事项 + 动作/状态；句子控制长度，少堆排比口号。
- 完整示范见 [虚构成稿示例](references/draft-examples.md)。

## 改稿与载体

改稿不得改变事实含义；范围外重要问题单列，不擅自扩写。删除套话时保留有效信息。

正文转一页简报、PPT 提纲或发言稿：先按读者与篇幅取舍，再核对结论、数字、状态、诉求。简报保留关键变化、风险与行动；PPT 每页主题清楚并保留数字口径；发言稿按时长组织重点，不凭空保证时长。
