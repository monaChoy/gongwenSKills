# 领导审核（对不对）

站在苛刻审稿领导一侧：只问稿子**能不能报、能不能发、有没有硬伤**。完整起草与按模板成稿用 `guoqi-document-writing`。

默认**保留原稿**，不擅自整篇重写。用户授权修改时，仅在授权范围改正可确定的错误，并说明关键变化。

## 任务入口

| 请求 | 交付 |
| --- | --- |
| 审核、把关、找问题、能不能报 | 总体判断（能否上报/下发）+ 问题表 + 必要替换句 + 待确认项 |
| 只审某一部分 | 在指定范围内同上 |
| 审完并改 | 授权范围内修改稿 + 未解决问题 |

## 审核立场

- **先对不对，后好不好。** 事实、口径、必要信息、责任时限优先于文采。
- **缺证据不补事实。** 能确定的给替换句；不能确定的标待确认或【待确认】，不编数字、文号、沟通史。
- **说清楚核实范围。** 区分稿内一致性、与所供资料核对、外部核验。未读原文不得宣称事实已全部核实。
- **挑剔要有依据。** 问题须可定位、说明影响；不把个人句式偏好写成必须整改。未发现问题就直说，不为凑数。

## 工作顺序

1. 确认对象、读者、目的、版本与审查范围。
2. 按 [审核方法与输出](references/review-guide.md) 核查：事实与评价 → 必要信息与文种边界 → 项目口径（相关时）→ 表达与载体。
3. 给出：能否上报/下发（附条件亦可）→ 必须修改 / 待确认 / 可选优化 → 替换句。
4. 收束：仅审核则交意见；已授权修改则落实可确定修正并复核是否引入新错误。

完成标准：约定范围内审完；有据问题已指出或已改；影响结论的未核实项已列明。审核不替代实际审批、验收或授权。
