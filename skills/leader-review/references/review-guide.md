# 审核方法与输出

用于已有稿件的苛刻把关。按文种、目的和材料选核查项，短通知不必套项目汇报全套。

## 1. 范围和依据

确认审查对象、读者、目的、版本与范围。缺关键信息时写明假设与待确认项，先完成能判断的部分。

核实范围可组合：

- **稿内一致性**：前后矛盾、遗漏、表达；未验证陈述是否符合实际。
- **原始资料核对**：与所供文件、清单、记录逐项核对，标明实际读取范围。
- **外部来源核验**：政策、标准、公开案例须查适用原文；未完成的列待确认。

已读原文与未读附件/转述分开。来源冲突时列差异，核统计期、范围、状态、版本；不因「更新」就认定全对，不自行平均或拼接新结论。

材料复杂时可用简表：「结论—来源位置—适用时间—口径—冲突/待办」；不必全部随意见交付。

## 2. 核查重点（按风险取舍）

### 事实与评价

- 阶段证据支持到哪，正文写到哪。拟配置清单不能证明已验收；合同、到货、安装、投运、验收各依原文，不互相推定。
- 核对单位、范围、分母、时间、限定词；「每项上限」≠「总额」；「报价」≠「批复预算」。
- 「已完成」「全面覆盖」「显著改善」须有证据；缺证据列待确认，不直接断假，也不补数。
- 原因、责任、承诺、成效分开查；依赖可写清，未经核实的责任判断不能写成客观结论。

### 必要信息与文种

只看成稿：读者能否独立理解核心结论、依据、状态与所需行动。

- 请示：拟决定事项是否可批复；一文是否多事。
- 通知：对象、事项、时限、方式是否可执行。
- 汇报/报告：问题与措施是否对应；风险是否被压缩删掉。
- 正式行文按已明确制度看文种边界；内部材料按会议/工作目的看，不强套一种格式。

### 项目类（相关时）

| 核查点 | 判断 |
| --- | --- |
| 状态与范围 | 规划/采购/实施/验收/运行各有据；现状与拟建边界清 |
| 经费与数量 | 口径、依据、清单与合计一致；未把报价写成已批 |
| 架构与清单 | 系统/设备/服务有用途与归属 |
| 协调事项 | 我方已做与对方待办可识别；时限未确认则保留拟定或标缺口 |
| 对标与旧模板 | 对标有来源与边界；旧项目专名数字未混入 |

### 表达与载体

分寸与证据相符；改套话不删有效信息。对比目标须有现状依据。

| 载体 | 标准 |
| --- | --- |
| 正文 | 前提、结论、依据、行动可独立理解；必要未知可见 |
| 一页简报 | 时间范围明确；保留变化、风险与行动 |
| PPT 提纲 | 主题与结论清楚；保留数字口径、状态、诉求 |
| 发言稿 | 与正文一致；口语化不扩大成果或承诺 |

仅有提纲时，不对版式与模板走样下结论。

## 3. 意见格式

先给**总体判断**：能否上报/下发，或「补证/修改后方可」。再列问题：

| 类型 | 位置与原文 | 依据及影响 | 建议或替换句 |
| --- | --- | --- | --- |
| 必须修改 / 待确认 / 可选优化 | 〔章节/段落及短句〕 | 〔来源或稿内矛盾；为何影响报发〕 | 〔可确定修正，或需核对的资料〕 |

- **必须修改**：已证实错误、稿内矛盾、错误引用/口径混用，或影响决策执行的必要信息缺失。
- **待确认**：原文未提供、材料冲突或依据不足。
- **可选优化**：不影响事实与使用的表达建议；不作通过前提。

仅缺证明时，验收、预算批复、覆盖成效等结论一律「待确认」。能确认「用方案当验收依据」「用报价当批复」或与有效原文矛盾时，列为必须修改。

替换句保留已知事实与限定；未知用【待确认】；拟定安排用「拟、建议、待审定」。定位用真实章节/原句，不虚构行号。

## 4. 收束

仅审核：意见 + 必要替换句。已要求修改：落实授权内可确定修正，简述变化与未决事项。只复核本次改动是否引入新的状态、数字、遗漏或立场变化。
