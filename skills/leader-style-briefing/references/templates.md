# 文种结构模板库

模板是默认结构，不是必选页序：按「读者需要知道什么、决定什么」增删；用户提供的格式模板优先。文中标注的数量（页数、条数）均为默认参考值，不是硬性要求。

## 模板一 · 信息化/项目前期建设思路汇报

适用：项目前期向业主或上级讲「怎么建」，争取认同与资源。

默认结构：政策依据 → 目标体系 → 总体架构 → 清单映射 → 实施与调研需求。

### 1. 政策依据

有与主题直接相关的上级文件时使用：文件全名 + 文号 + 印发时间，拆成 3–4 个发力点，后续章节回挂到发力点。没有直接相关文件就从业务需求立论，不硬挂政策。

发力点写法：动宾短语领起 + 一句具体化。

> 例：加快监测感知体系建设——重点实施安全监测设施的更新改造，构建一体化全要素动态监测感知体系。

### 2. 目标体系（转变对句式）

每条目标用「旧方式 → 新方式」成对跃迁句式，覆盖关键维度即可（默认 5–7 条）。有可靠来源时配对标案例：项目名 + 硬数字 + 一句话成效；案例明确标注为对标项目，与本项目事实区分。

转变对句式库（按维度选用或自造）：

| 维度 | 句式 |
| --- | --- |
| 感知 | 感知全面化与监控全天候 |
| 控制 | 从「人跑腿」到「数据跑路」 |
| 决策 | 从「经验判断」迈向「算力决策」 |
| 配置 | 从「粗放」迈向「精准」 |
| 业务 | 业务应用一体化与全生命周期管理 |
| 巡检 | 从「徒步巡查」转向「天空地水人」一体化 |

自造方法：① 找旧方式的典型动作（人跑腿、徒步巡查、经验判断）；② 找新方式的核心机制（数据跑路、立体巡检、算力决策）；③ 两边都具体有画面，换掉「提升」「加强」这类无对立的词。

> 对标案例模板：例如〔对标项目名〕布设〔N〕路视频监控，实现「一屏观全域」。

### 3. 总体架构

要害是思维不是目录：先立分层、分组件的总体架构，让清单成为架构的实例。架构从同类成熟项目的参考框架借来、按本项目裁剪——分几层、分哪些模块，以项目实际为准。

水利数字孪生领域的一种常见分法（只作参照，不作规定）：信息化基础设施 / 数字孪生平台（数据底板 + 模型平台 + 知识平台）/ 业务应用 / 网络安全体系 / 保障体系。

**颗粒度标尺**：展开到读者能理解、评估、决策所需的层次为止——通常每个「模型」数得出子模型、每类「数据」数得出类别；功能单一、边界清楚的模型按功能、输入输出或组成说明即可，不强拆子模型。

### 4. 清单映射

采购清单按各项实际属性映射到架构对应层或保障部分（系统、设备、服务分开），保留原始清单的名称、单位与数量。摘要可压成一页「包括建设 X 系统 1 套，Y 设备 N 台……」；清单复杂、需要逐项核对时另附明细表，不硬压成一段。

### 5. 实施与调研需求

调研需求问「设计输入」——拿到答案后能定界、画图、算量的问题。常见六类，按需选用：

| 类别 | 问法要点 | 拿到答案后能做什么 |
| --- | --- | --- |
| 利旧盘点 | 现有设施及运行情况 | 定利旧与新增的边界 |
| 底板范围与精度 | 区域范围（航飞、建模范围），DEM/DOM 精度 | 定数据采集与建模工作量 |
| 建模对象 | 区域内有什么建筑物、机电设备 | 定建模清单 |
| 用户与权限 | 管理方之外还有哪些使用群体（公众？上级单位？） | 定权限体系与多端设计 |
| 建设周期 | 系统工期 | 排实施计划与关键路径 |
| 预算口径 | 见下 | 统一对外口径 |

预算口径按当前实际资料表述，区分估算、概算、报价、批复预算；不预设此前沟通历史或范围变化——没有依据就不写「以前提过」「现在增加了」。

行政协调事项（对接人、时间安排）是否写入取决于文件目的：建设思路中可略；需要对方行动时必须写成需协调事项（见模板二要点）。

## 模板二 · 项目信息/进展汇报

适用：周期性或节点性的进展同步；读者要掌握状态、风险与需协调事项。

默认结构：核心结论 → 项目概况与当前状态 → 计划与实际（偏差及原因）→ 问题风险及措施 → 下一步安排 → 需协调/决策事项。

要点：

- 进展与偏差写实际口径（完成量、节点对比）；延期写清原因、影响范围与补救措施。
- 依赖与协调如实写：上游输入未到位等依赖 = 我方已做措施 + 需对方在何时完成什么。
- 无政策、无案例也可成文；不为凑结构增添材料。

## 模板三 · 专项工作汇报/总结

默认结构：总体情况 → 重点工作与成效 → 存在问题 → 后续安排。

要点：成效给可核实证据（数字、验收结论、评价）；存在问题写实不回避，并与后续安排中的整改措施一一对应。

## 模板四 · 请示

默认结构：拟请示事项 → 理由与依据 → 方案、资源及影响 → 拟提请决定的内容。

要点：一文一事；金额、数量、时限给出依据（估算口径注明）；拟提请决定的内容写成可批复的表述。

## 模板五 · 情况说明

默认结构：事项背景 → 已核实事实与时间过程 → 原因及影响 → 已采取措施与后续安排。

要点：只写已核实事实，时间线精确；原因区分直接原因与待查证因素，后者标注核实方式与时限。

## 模板六 · 通知

默认结构：事项与对象 → 具体要求 → 责任、时限及办理方式。

要点：每条要求可执行、可检查——谁、在什么时间前、做什么、通过什么方式反馈。
