# 公文写作技能组合

本项目用于整理和维护面向实际工作场景的公文写作技能，重点服务维护者的日常写作需求。技能可以围绕具体业务、文种和收文对象逐步细化，不要求覆盖所有公文写作场景。

当前以**中国国企/央企材料**为主线（事实口径与把关），区别于通用政府公文风格引擎。架构上借鉴公开参考库 lieflat-gongwen 的单入口、文种路由、先骨架后完整成稿、虚构范文与披露块等组织法；**不**移植其参数卡、语料 DNA、自检脚本或范文正文（对方许可为 PolyForm Noncommercial）。后续业务方向以实际需求和经脱敏的材料为依据，不预设具体岗位、行业或项目情况。

每个技能放在 `skills/<技能名>/` 下，包含 `SKILL.md` 及其配套参考文件。

## 组织原则

- 通用方法与业务场景分开维护：事实核查、语体、结构选择等共性规则保留在基础技能中；业务专属术语、结构和核查点按需要写入参考文件或独立技能。
- 简单的场景差异优先补充参考模板；只有工作流程或适用条件明显不同时，再拆分独立技能，避免重复维护。
- 工作适用性与公开可复用性兼顾：保留业务方法，使用通用占位符和虚构示例，不收录可识别的内部项目材料。

## 脱敏要求（强制）

编写或更新技能时必须脱敏，覆盖技能正文、参考模板、示例、文件名、附件及元数据。

- 不得包含真实项目名、可识别的单位或人员名称、联系方式、内部地址、账号凭证及本机绝对路径。
- 项目、单位、人员与数量使用 `〔项目名〕`、`〔单位〕`、`〔人员〕`、`〔N〕` 等通用占位符。
- 能通过时间、地点、金额、规模或其组合识别具体项目的内容也必须泛化；只替换项目名不算完成脱敏。
- 从工作材料提炼结构、方法与核查点，不将内部原文或可识别案例放入仓库。
- 每次交付及公开发布前，逐份检查全部新增或修改文件，包括尚未纳入版本管理的文件；提交说明中记录脱敏检查结果。

## 技能体系与补充方向

围绕「材料与来源 → 起草/改稿 → 领导审核 → 文件制作与交付」组织能力。

| 环节 | 当前安排 | 补充条件与方向 |
| --- | --- | --- |
| 材料与来源 | 主 skill 区分事实、计划、建议与待核实 | 重复检索/版本比对任务增多时再补参考 |
| 起草与改稿 | `guoqi-document-writing`：路由、骨架、完整成稿、指定模板优先 | 按使用频率补虚构成稿；业务差异先入 references |
| 领导审核 | `leader-review`：对不对、可定位意见 | 按漏检完善案例 |
| 文件制作与交付 | 主 skill 覆盖简报/PPT/发言稿内容要求 | 成品版式用环境中可用工具，先确认能力再承诺 |
| 效果验证 | 虚构示例作行为检查 | 同模型、同资料对比无技能与有技能版本 |

当前优先完善高频文种例稿与审稿案例；不扩充大而全文种目录，不把参数化风格引擎引入本仓。虚构示例是行为检查依据，不等于完成生成效果对比。
