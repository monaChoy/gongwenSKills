# 公文写作技能组合

本项目用于整理和维护面向实际工作场景的公文写作技能，重点服务维护者的日常写作需求。技能可以围绕具体业务、文种和收文对象逐步细化，不要求覆盖所有公文写作场景。

当前以国企场景的文件写作与审核把关方法为基础；后续业务方向以实际需求和经脱敏的材料为依据，不预设具体岗位、行业或项目情况。每个技能放在 `skills/<技能名>/` 下，包含 `SKILL.md` 及其配套参考文件。

## 组织原则

- 通用方法与业务场景分开维护：事实核查、语体、结构选择等共性规则保留在基础技能中；业务专属术语、结构和核查点按需要写入参考文件或独立技能。
- 简单的场景差异优先补充参考模板；只有工作流程或适用条件明显不同时，再拆分独立技能，避免重复维护。
- 工作适用性与公开可复用性兼顾：保留业务方法，使用通用占位符和虚构示例，不收录可识别的内部项目材料。

## 脱敏要求（强制）

编写或更新技能时必须脱敏，覆盖技能正文、参考模板、示例、文件名、附件及元数据。

- 不得包含真实项目名、可识别的单位或人员名称、联系方式、内部地址、账号凭证及本机绝对路径。
- 项目、单位、人员与数量使用 `〔项目名〕`、`〔单位〕`、`〔人员〕`、`〔N〕` 等通用占位符。
- 能通过时间、地点、金额、规模或其组合识别具体项目的内容也必须泛化；只替换项目名不算完成脱敏。
- 从工作材料提炼结构、方法与核查点，不将内部原文或可识别案例放入仓库。
- 每次交付及公开发布前，逐份检查全部新增或修改文件，包括尚未纳入版本管理的文件；提交说明中记录脱敏检查结果。

## 使用方式

使用时读取对应技能的 `SKILL.md`，按请求进入起草、改稿或审核方式；用户提供的资料、格式、结构与篇幅要求优先。技能的名称和调用设置保持原样，不作改动。

| 请求示例 | 交付 |
| --- | --- |
| 根据这些材料写一份进展汇报 | 成稿，并列出影响使用的信息缺口 |
| 润色这份请示，保留数字和请求事项 | 修改稿及关键改动说明 |
| 审核这份报告，重点看事实与经费口径 | 总体判断、可定位的问题、必要的替换句及待确认项 |

起草与改稿包含内容自查；单独审核默认交付意见，不擅自整篇重写。用户要求修改或同时要求写作与审核时，按授权范围落实可确定的修正。

参考文件按需读取：

- [文种结构模板](skills/leader-style-briefing/references/templates.md)：七类结构及配套载体转换要点。
- [审核方法与输出](skills/leader-style-briefing/references/review-guide.md)：核实范围、检查重点、问题分级及意见格式。
- [虚构审稿案例](skills/leader-style-briefing/references/review-examples.md)：阶段与预算误写、限定词保护、来源冲突、通知审查、跨载体压缩与旧模板内容混入。

## 写作与审核是否拆分

目前保留一个技能、多个工作入口。起草、改稿和审核共用事实与口径规则，也经常在同一任务中衔接；独立的审核输出与核查方法放在参考文件中，避免主文件膨胀或重复维护。

以下情况持续出现时，再考虑独立审核技能：

- 审核读者、适用制度或授权范围显著不同，例如形成独立的专业审查工作流。
- 审核需要稳定、独立的工具或证据链，现有按需参考方式已不能清楚表达。
- 经虚构用例和实际脱敏任务验证，写作与审核入口经常混淆，且仅调整描述与路由仍不能解决。

拆分时，共用规则只保留一份，通过明确引用维护；仅因阶段名称不同或检查项变多，不新增同质技能。

## 技能体系与补充方向

围绕“材料与来源 → 起草/改稿 → 内容审核 → 文件制作与交付”组织能力；本仓库目前只有上述一个技能，其他层按任务和实际工具条件组合。

| 环节 | 当前安排 | 补充条件与方向 |
| --- | --- | --- |
| 材料与来源 | 本技能区分事实、计划、建议与待核实信息；重要或冲突材料按需记录来源 | 出现重复的检索、版本比对或材料整理任务时，补充来源管理参考；只有检索工作流明显独立时再拆技能 |
| 起草与改稿 | 本技能按文种和读者选择结构，保持事实、限定条件与诉求不走样 | 依据常用任务补充脱敏完整例稿；业务差异先进入参考文件 |
| 内容审核 | 本技能提供可定位、有依据的意见和必要的替换句 | 根据实际漏检完善用例；专业制度或技术审核有独立要求时另行设计 |
| 文件制作与交付 | 本技能覆盖正文、简报、PPT 提纲与发言稿的内容要求 | 需要成品 Word、PPT、修订或版式检查时，组合环境中可用的专用工具；先确认实际能力再承诺交付 |
| 效果验证 | 虚构案例说明预期行为，可用于人工检查 | 采用同一模型、相同原始资料和输出要求比较无技能、现有版与调整版，记录错误、遗漏及修改负担 |

当前优先完善审稿案例、来源冲突处理和常用文种例稿，不扩充大而全的文种目录，不把具体工具操作复制进通用写作技能。虚构示例是行为检查依据，不等于完成生成效果对比。
